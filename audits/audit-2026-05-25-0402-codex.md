## 8. Specific Questions for the Phase 4 Layer

1. **Is the replay format ready for the eval harness?** **Not on the public harness path.** The schema is mostly ready when a runner is explicitly configured: `MeetingReplayEntry` carries transcript, ballots, contradictions, `llm_calls`, prompt versions, and state hashes (`orchestrator/replay.py:86-116`), and per-call cost can be summed from `LLMCallRecord.cost_usd` (`:51-72`). But `scripts/run_game.py` and `eval.balance_eval.run_balance_eval` do not install a runner, so the required audit tournament wrote zero meeting entries; the eval harness would see no meeting artifacts from those commands.

2. **Does the meeting interpose point allow Phase 4 WebSocket broadcasts?** **Only after the fact today.** `DefaultMeetingRunner.run_meeting` calls `MeetingManager.run(...)` as one async block and returns final `MeetingArtifacts` at `orchestrator/game.py:282-297`; there is no callback/event stream for report submitted, round started, statement collected, or vote cast. Phase 4 can broadcast completed meeting records, but live incremental meeting broadcasts will need instrumentation around the manager phases.

3. **Any Anthropic-specific assumptions in `reasoner.py` or `manager.py`?** **No blocking coupling found.** The required grep for `anthropic|cache_control|extended_thinking` under `agents/`, `meetings/`, and `orchestrator/` is empty. A broader prompt grep found only schema placeholders like `<int>` / `<player_id>` in `.j2` templates, not provider-specific XML tags.

4. **Does cost tracking support the ≤ $0.30/game check?** **Extraction yes, enforcement no.** Replay cost extraction is a simple sum over `MeetingReplayEntry.llm_calls[*].cost_usd` when meeting entries exist. Enforcement is not wired into the default meeting/orchestrator flow: `DefaultMeetingRunner` accepts raw `LLMClient` and wraps it only for recording at `orchestrator/game.py:240-254`; `BudgetedLLMClient` has no production call site.

5. **Did Phase 3 introduce new Phase 2 risks?** **Yes in the public meeting path.** The old six-seed results and decisive split still reproduce, and leak/byte identity pass for tick-only runs. But the tournament still reports 7 non-completions at `MEETING_PHASE_REACHED`, which Phase 3 was supposed to remove from the full-game harness.

6. **New Critical/High findings introduced by this audit window?** **Yes: 1 Critical and 1 High.** The Critical is the no-runner public harness / surviving `MEETING_PHASE_REACHED` path. The High is missing budget-wrapper wiring into the actual meeting/orchestrator flow.

7. **Is the substrate ready for Phase 4 dispatch after real-provider eval passes?** **No.** The real-provider eval should not run yet; Phase 4 would otherwise build spectator/eval UI on replay streams that currently omit meetings in the public harness and on game execution that does not enforce the per-game budget.

The new unit-level tests are generally strong: prompt-loader tests use strict undefined and schema round-trips; voting tests cover SKIP plurality, ties, threshold inclusivity, hallucinated/self targets, and order independence; contradiction tests include consistent no-flag cases, true positives, determinism, and shared-schema round trips.

The main false-positive risk is integration scope. Orchestrator tests prove meetings work only when `meeting_runner` is passed explicitly, while two tests preserve the legacy pause behavior (`tests/orchestrator/test_game.py:220-230`; `tests/orchestrator/test_meeting_integration.py:424-444`). That lets `pytest` and `check.sh` go green while `scripts/run_tournament.py` still produces `meeting_phase_reached:7`.

The budget tests prove `BudgetedLLMClient` works in isolation and with a `StrategicReasoner`, but no test asserts that `DefaultMeetingRunner`, `HeadlessGame`, `scripts/run_game.py`, or `run_balance_eval` actually receives a budgeted client. The R-9 long-horizon replay test is valuable, but it uses a monkeypatched corpse and configured runner; it does not cover the public seed/harness command the eval prompt will run.

## 10. Defects and Risks

### C-1 [Critical] Public game/tournament harness still pauses at `MEETING_PHASE_REACHED`

- **Status:** Open; blocks real-provider eval and Phase 4.
- **Evidence:** `HeadlessGame.run` returns `MEETING_PHASE_REACHED` when `state.phase == "MEETING"` and `_meeting_runner is None` at `orchestrator/game.py:645-651`; `scripts/run_game.py:71-80` constructs `HeadlessGame` without `meeting_runner`; `eval/balance_eval.py:112-120` does the same for every tournament game. The required 100-game command returned `meeting_phase_reached:7`, and a replay count found `meeting_entries=0`.
- **Why it matters:** Phase 3 merge criteria require fake-provider full games to complete end-to-end with meetings. The public harness still exercises the Phase 2 early-stop path instead, so the real-provider eval would not validate meetings, replay meeting artifacts, or cost per meeting.
- **Recommended action:** Make the default CLI/tournament path meeting-enabled with a fake-provider `DefaultMeetingRunner` (and budget wrapper), remove or quarantine the legacy no-runner outcome from the Phase 3 full-game path, and add a CI test that runs the public harness through at least one real meeting and asserts no `MEETING_PHASE_REACHED`.

### H-1 [High] Budgeted client and reasoner checks are bypassed by the actual meeting flow

- **Status:** Open.
- **Evidence:** `grep -rn "BudgetedLLMClient" orchestrator/ meetings/ agents/strategic/` is empty. `DefaultMeetingRunner` accepts raw `LLMClient` and constructs `_RecordingLLMClient` at `orchestrator/game.py:240-254`; the recording wrapper captures replay telemetry but does not hold a `GameBudget`. `MeetingManager` renders prompts and calls `self._llm_client.complete(...)` directly at `meetings/manager.py:512-528`, `560-579`, and `644-662`, bypassing `StrategicReasoner`'s scanner path. A production-use grep for `StrategicReasoner` outside tests/docs finds no orchestrator/meeting call site.
- **Why it matters:** Task 3.9's C-5 acceptance gate was meant to close budget wiring, and the R-10 scanner gate only protects production if production strategic prompt inputs flow through the reasoner or equivalent wrapper. As-is, live meetings can spend past the per-game cap until after replay cost analysis, and the actual meeting path does not run the reasoner's strategic prompt-input scanners.
- **Recommended action:** Thread one `GameBudget` per game into the default meeting runner via `BudgetedLLMClient`, and either route meeting prompt construction through `StrategicReasoner` or extract its scanner into the meeting path with a regression proving `DefaultMeetingRunner`/`HeadlessGame` trips a planted prompt-input leak.

### R-1 [Concern] `LLMCallRecord` lacks per-call prompt-version / parsed-output fields

- **Status:** Open concern, not counted as Critical because the meeting entry carries the four categories at the meeting level.
- **Evidence:** `LLMCallRecord` fields are `call_kind`, `model`, `prompt`, `response_text`, token counts, and `cost_usd` at `orchestrator/replay.py:51-72`; `prompt_versions` is a separate meeting-level mapping at `:113-114`, and parsed outputs live in `transcript` / `ballots` / `MeetingResult`.
- **Why it matters:** Phase 5 tooling can sum cost and render transcript today, but correlating a particular raw LLM response to a prompt template version requires inference from prompt text or call order. The audit prompt asked for `prompt_version` and parsed output on `LLMCallRecord`; the current design stores equivalent data, but not per-call.
- **Recommended action:** When fixing C-1/H-1, decide whether to add per-call `prompt_id`/`prompt_version`/parsed-output metadata or explicitly document the meeting-level mapping as the supported replay contract.

## 11. Document Conflicts

- **Task 3.12 / audit prompt vs code:** Task 3.12 says gameplay resumes after meetings and R-9 replay artifacts are recorded (`tasks/phase-3.md:931-935`); the public `HeadlessGame` path still returns `MEETING_PHASE_REACHED` without a runner (`orchestrator/game.py:645-651`), and tests explicitly preserve that legacy behavior.
- **Phase 3 merge criteria vs tournament harness:** `tasks/phase-3.md` merge criteria require full-LLM fake-provider games and replay meeting artifacts, but `eval/balance_eval.py:9-15` still treats `MEETING_PHASE_REACHED` as a normal non-decisive bucket and `:112-120` does not pass a meeting runner.
- **Task 3.9 C-5 wording vs production wiring:** The task contract says `BudgetedLLMClient` should wrap calls and that consumers including `MeetingManager` accept it (`tasks/phase-3.md:686-687`), but production meeting construction still receives raw `LLMClient`.

## 12. Readiness for Phase 4

**Not ready for Phase 4, and not ready for the real-provider eval.** Static code quality, firewall, prompt-loader, voting, contradiction detection, and replay schemas are mostly in good shape, but Phase 4 would consume the same public replay/game paths that currently omit meetings. The remaining real-provider gate is explicitly out of scope for this audit; it should run only after the Critical no-runner harness defect and the High budget-wiring defect are fixed. Once those two are closed, the existing replay schema is close to useful for spectator UI and eval metrics, with the per-call prompt-version concern to resolve or document.
